# JamVPN — контекстный документ

Документ описывает архитектуру, текущее состояние и технические ограничения приложения
для планирования дальнейшей разработки. Актуально на 2026-06-11.

---

## 1. Что это

JamVPN (бренд AlphazetVPN) — десктопный VPN-клиент под Windows. Один исполняемый файл,
без инсталлятора и (для большинства протоколов) без внешних зависимостей. Управление
профилями, подключение/отключение, импорт конфигов, диагностика сети, системный трей.

**Назначение:** дать пользователю подключаться к VPN-серверам разных протоколов из единого
GUI, по возможности без ручной настройки Windows.

---

## 2. Технологический стек

| Слой | Технология |
|------|-----------|
| Каркас приложения | [Wails v2](https://wails.io) v2.12.0 (Go ↔ WebView2 мост) |
| Backend | Go 1.26 |
| Frontend | Один файл `frontend/index.html` (~1860 строк, ванильный HTML/CSS/JS, без сборщика) |
| Трей | `getlantern/systray` |
| VPN-движки | Windows RAS, `wireguard-go`+wintun, `xtls/xray-core` (in-process), OpenVPN (опц.) |
| Хранилище | JSON-файл `%APPDATA%\JamVPN\profiles.json` |

Сборка: `wails build` (production) или `go build ./...` (проверка компиляции).
Бинарь коммитится в репозиторий (`build/bin/JamVPN.exe`).

## 3. Карта модулей

```
main.go                     — точка входа Wails, конфигурация окна
app.go                      — App: методы, экспонируемые во frontend (Connect, SaveProfile, Import…)
tray_windows.go             — системный трей, быстрое подключение
internal/
  config/
    profile.go              — модель Profile, TunnelType, состояния соединения
    store.go                — CRUD профилей в JSON, миграции (OpenVPN→Xray по URI)
  vpn/
    manager.go              — Manager: единое активное соединение, статусы, монитор разрывов
    ras_windows.go          — L2TP/SSTP/IKEv2/PPTP через Windows RAS (rasdial + Add-VpnConnection)
    wireguard_windows.go    — встроенный WireGuard (wireguard-go + wintun.dll)
    wintun_windows.go       — извлечение встроенного wintun.dll рядом с exe
    xray.go                 — in-process Xray (VMess/VLESS/Trojan/Shadowsocks) + системный прокси
    proxy_windows.go        — установка/снятие системного прокси через HKCU (без админа)
    openvpn.go              — запуск openvpn.exe
    openvpn_embed_windows.go— встраивание openvpn.exe (build tag `with_openvpn`)
    hidewindow_windows.go   — скрытие консольных окон дочерних процессов
  parser/                   — импорт: WireGuard .conf, .ovpn, URI-схемы, JSON
  qr/                       — генерация/чтение QR, share-ссылки jamvpn://
  nettest/                  — ping (TCP) и speedtest (Cloudflare)
  logger/                   — лог в память + файл %APPDATA%\JamVPN
  trayicon/                 — генерация иконки трея
```

**Поток подключения:** frontend → `App.Connect(id)` → `Manager.Connect(profile)` →
`runConnect` (горутина) → диспетчеризация по `TunnelType` → протокол-специфичная функция.
Статус публикуется во frontend каждые 2 сек событием `vpn:status` (тикер в `app.go`).

## 4. Протоколы: матрица возможностей

| Протокол | Механизм | Админ-права | Внешние зависимости | Статус |
|----------|----------|:-----------:|:-------------------:|--------|
| **L2TP/IPsec** | Windows RAS (`rasdial`) | **Да** | нет (встроено в Windows) | Работает¹ |
| **SSTP** | Windows RAS | **Да** | нет | Работает |
| **IKEv2** | Windows RAS | **Да** | нет | Реализован, мало тестов |
| **PPTP** | Windows RAS | **Да** | нет | Реализован (устаревший, небезопасный) |
| **WireGuard** | wireguard-go + wintun | **Да** (TUN-адаптер, маршруты) | wintun.dll (встроена) | Реализован |
| **Xray** (VLESS/VMess/Trojan/SS) | in-process xray-core + системный прокси | **Нет** | нет (всё в процессе) | Реализован |
| **OpenVPN** | внешний/встроенный openvpn.exe | **Да** | openvpn.exe (build tag) | Опционально |

¹ L2TP за NAT требует ключа реестра `AssumeUDPEncapsulationContextOnSendRule=2`,
который применяется **только после перезагрузки Windows**.

### Ключевой архитектурный вывод
- **Без админ-прав работает только Xray** — он крутится в одном процессе и ставит лишь
  пользовательский прокси через HKCU. Это единственный по-настоящему автономный путь.
- **L2TP/SSTP/IKEv2/PPTP** принципиально требуют админ-прав: они управляют встроенной
  службой Windows RAS, а часть настроек (NAT-ключ L2TP) лежит в HKLM. Манифест приложения
  поэтому объявляет `requireAdministrator`.
- **WireGuard** автономен по бинарям, но тоже требует админ-прав (создание сетевого адаптера
  и правка таблицы маршрутов).

**Принятое решение (2026-06):** L2TP/SSTP остаются основными, админ-права приняты как
данность. Манифест `requireAdministrator` менять не планируется.

## 5. Текущее состояние

### Что работает
- Подключение и удержание L2TP и **SSTP** (проверено на боевом сервере `vpn.a-zet.ru`).
- Создание/обновление/удаление профилей, импорт из URL/текста/файла/QR, экспорт, share-ссылки.
- Системный трей с быстрым подключением, диагностика (ping/speedtest).
- Идемпотентное создание RAS-записи (не падает на оставшихся записях от прошлых попыток).
- Корректное определение статуса соединения и разрывов на уровне ОС.

### Недавно исправленные баги (см. историю git)
1. **Игнорирование полей профиля** — `addVPNConnection` жёстко слал `MSChapv2`; теперь
   учитывает метод аутентификации, шифрование, split-tunneling из профиля.
2. **Неверный обход сертификата SSTP** — писали в `WinHttp\DisableRevocation` (не работает);
   теперь `SstpSvc\Parameters\NoCertRevocationCheck`.
3. **Дефолт шифрования `Optional`** ронял соединение через ~3 сек (сервер требует шифрование);
   теперь при невыбранном значении флаг опускается → Windows по умолчанию `Required`.
4. **Кракозябры в ошибках** — вывод PowerShell читался как UTF-8 вместо OEM; добавлен форс UTF-8.
5. **`RASCONN` pack(4)** — Go-структура с естественным выравниванием (1392 Б, offset 8/16)
   отвергалась `RasEnumConnectionsW` (ERROR_INVALID_SIZE), из-за чего любое живое соединение
   считалось разорванным. Переписано на сырой буфер (size 1388, handle@4, name@12).

### Изменения v2.3.0 (2026-08)
1. **Single instance.** Повторный запуск exe больше не плодит второй процесс и вторую
   иконку в трее: `SingleInstanceLock` (мьютекс Windows) в `main.go`. Второй запуск
   активирует окно работающего экземпляра и передаёт ему свои аргументы: jamvpn://-ссылки,
   протокольные URI, http(s)-URL и пути к .conf/.ovpn/.json импортируются на лету
   (событие `profiles:imported` обновляет UI).
2. **Корректный выход.** «Выйти» из трея при активном VPN спрашивает подтверждение
   (Yes/No MessageBox), затем дожидается реального отключения (таймаут 8 с) и лишь потом
   завершает процесс. Хак `os.Exit(0)` через 500 мс убран; причина зависания процесса
   была в том, что `runtime.Quit` повторно вызывает `OnBeforeClose`, а тот всегда прятал
   окно и отменял выход — теперь во время выхода `OnBeforeClose` пропускает закрытие.
3. **Настройки закрытия/старта наконец работают.** `close_action: quit` закрывает
   приложение по ✕ (раньше всегда пряталось в трей), `start_minimized` запускает окно
   скрытым (`StartHidden`; настройки читаются в `main()` до `wails.Run`).
4. **Гонки устранены:** `selectedTrayProfileID` и антидребезг трея (`lastTrayKey`)
   защищены мьютексами; подписка на события трея больше не оборачивается в лишнюю горутину.
5. **Импорт share-ссылок jamvpn://** — собственные ссылки приложения теперь парсятся
   (`parseJamVPNURI`), раньше «Импорт из текста» на них падал.
6. **Миграция старых профилей** ищет `vpn_profiles.json` относительно каталога exe,
   а не рабочего каталога (автозапуск/ярлыки запускают exe с произвольным CWD).
7. **Unit-тесты** на `internal/parser`, `internal/config` и чистые хелперы `main`.

### Известные проблемы / технический долг
- **Накопление осиротевших RAS-записей** в Windows от тестов (нет кнопки массовой очистки).
- **WireGuard/IKEv2/PPTP** почти не протестированы на реальных серверах.
- **Frontend — один файл** без сборщика, тестов и компонентов.
- **UI-тестов нет** (Go-тесты на парсеры/хранилище появились в v2.3.0).
- **Нет автообновления** приложения.
- **Бинарь (35 МБ) коммитится в git** — репозиторий пухнет с каждой сборкой.
- **Только один профиль активен одновременно** (см. `Manager.current`).
- **Нет измерения трафика** (`BytesSent/BytesRecv` в статусе не заполняются для RAS).

## 6. Технические ограничения и подводные камни

- **`requireAdministrator`** — приложение всегда запрашивает UAC. Без этого L2TP/SSTP/WG не работают.
- **L2TP за NAT → перезагрузка.** NAT-ключ читается только при загрузке Windows.
- **`RASCONN`/`RASCONNSTATUS` упакованы по 4 байта.** Нельзя описывать их обычными Go-struct —
  только сырой буфер с ручными смещениями (handle@4, name@12, size 1388 / status 564, state@4).
- **PAP/CHAP несовместимы с MPPE** — при их выборе уровень шифрования принудительно `Optional`
  (транспорт L2TP/SSTP всё равно шифруется на уровне IPsec/TLS).
- **Имена соединений на кириллице** работают (Add-VpnConnection/rasdial/enum), но логи в .log-файле
  стоит открывать в UTF-8, иначе кириллица выглядит как мусор.

### Открытый стратегический вопрос
Если приоритет — **работа без админ-прав**, то целевой путь это Xray (+ возможный tun2socks
для полного туннеля), а RAS-протоколы становятся «для опытных». Если приоритет — **L2TP/SSTP
совместимость с корпоративными серверами**, то админ-права остаются и фокус на надёжности RAS.
Эти два вектора стоит развести явно в роадмапе.
